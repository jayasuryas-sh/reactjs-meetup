The problem I had.

The problem I had

Many agents, one terminal, zero visibility

  • Multiple tasks in flight means multiple agents running at once
  • Hard to tell what's working, what's idle, what's blocked
  • Every check-in means hopping across panes and tabs
  • Accidentally close the terminal? Your agent dies with it
  • Named your session and remembered the name? Lucky you. Not me.
What I did

Went looking for a better way

  • Found Conductor: a Mac GUI that runs parallel agents in isolated workspaces
  • Nice, but felt heavy for me with multiple workspaces open
  • And my home is the terminal, I didn't want to leave it
  • Then I found herdr
The fix

herdr: an agent multiplexer

  • Many agents, many workspaces, one window
  • A TUI you can click and drag, no keyboard wizardry required
  • Always know which agent is working, idle, or blocked
  • Ships skills: plain English instead of commands ("split a pane, show the logs")
  • Close it anytime. Type herdr. Everything is back.

What if we gave our agents more power to verify what we build?

The answer

agent-browser

  • A browser automation CLI for AI agents, from Vercel
  • Not test cases: agents verify your UI and user flows in a real browser
  • Snapshots, auth vault, a11y audits, React DevTools integration, and more
  • Built token-efficient
  • Ships skills too: "run an accessibility audit" is a sentence, not a command
Better together

Now combine the two

  • Every worktree gets its own agent and its own browser
  • Multiple features tested simultaneously, each in an isolated instance
  • Bugs surface before I ever open the browser myself
  • Fast, ergonomic, token-light, React-aware
