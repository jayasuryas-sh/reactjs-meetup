Stop Paying for Instructions Your Agent Doesn't Need

Keeping your CLAUDE.md lean, and why it just got easier

CLAUDE.md loads before your first word.

The file

CLAUDE.md loads before your first word

  • Read at the start of every session, whatever the task
  • Written once, appended forever, audited never
  • Ours: 938 lines, about 7,000 tokens, before I'd typed anything
  • Five parallel agents means you pay it five times
The problem

Two reasons bloat hurts

  • Tokens: every unneeded line is paid for on every task
  • Adherence: the more lines, the more the model ignores
  • Docs: "Bloated CLAUDE.md files cause Claude to ignore your actual instructions."
  • The file you made longer to make it behave is why it stops behaving

How to optimise it.

Move 1

Delete what the repo already answers

CLAUDE.md, today − remove   ✓ keep
## Tech Stack: React 18, TypeScript 5, Redux, Vite# already in package.json
## Project Structure: app/components, app/containers, app/services# one ls away
## Imports: import Box from '../Box'# visible in any file
Keep components small and focused.# generic advice
components/ never hold Redux state; containers/ own it# a real contract, unguessable
Scaffold with npm run generate, don't hand-write boilerplate# a local command
Move 2

Split the rules, load them by path

  • Styling, containers, tests: they don't all matter on every task
  • Each becomes its own file under .claude/rules/, tagged with the paths it applies to
  • Touch a test, the testing rules load. Touch a service, they don't.
Working on… → which rule loads
A container or Redux slice.claude/rules/containers.md
Styling, theme, Box / Flex.claude/rules/styling.md
Writing tests.claude/rules/testing.md
inside testing.md
paths: ["**/*.test.tsx"]# loads only for test files
Query by role, not by test id: screen.getByRole('button')# one testing rule
Move 3

Point, don't paste

CLAUDE.md − remove   ✓ keep
## Redux pattern: 265 lines of reducer, saga, and selector code# copied from a real folder
Redux pattern: see app/containers/OrderHistory# a pointer can't go stale
## Custom hooks: useCart, useAuth, useDebounce, useToggle ...# listed 10, the repo has 40
Hooks live in app/utils/use*.ts, read them there# the real list, always current
## Styling (the same rules again, already in section 4)# duplicate: one rule, one home

A pointer can't go stale. A copy always does.

Move 4

Must never slip? Not prose.

CLAUDE.md − remove   ✓ keep
Never read .env files.# a permission, not a sentence
Never leave console.log in committed code.# a lint rule, not a sentence
.claude/settings.json
"permissions": { "deny": ["Read(./.env)"] }# the agent can't read it, ever
.eslintrc
"no-console": "error"# the build fails, every time

Prose gets skimmed. Automation runs every time and costs zero tokens.

Did quality hold?

We checked before trusting it

  • Same real feature, built ten times: five old setup, five new
  • Sandboxed: git history stripped, pass criteria written first
  • 10 / 10 complete, compiling, tests green
  • One task, ten runs. Directional, not a study. Claim: same quality, lower cost.

You don't have to do everything I did.

The easy way

Two commands do most of this now

  • /doctor inside a session (2.1.206+): flags what the repo already says
  • /prompt-audit (2.1.221+): flags what the model no longer needs telling
  • Both propose the change. You read the diff, then accept
  • Reading that diff is your eval, for a file this size

Why are we suddenly talking about this?

Why now

The models changed. Our files didn't.

  • Older models needed rules, guardrails, step-by-step babysitting
  • Those lines are now dead weight for the models we actually run
  • Worse than dead weight: old instructions confuse the model, or hold it back from what it would do on its own
  • Boris Cherny, roughly: "every six months, delete your CLAUDE.md and see what the model does"
Do this tomorrow

The ten-minute checkup

  • /context in a fresh session: see what you pay before typing
  • /doctor, then /prompt-audit: read the diffs, accept
  • Deep, folder-specific rules → .claude/rules/ with paths:
  • Must-never-slip rules → permissions, hooks, or lint
  • Go deeper: Anthropic, "The New Rules of Context Engineering for Claude 5 Generation Models"
